# Heuristic Evaluation: OWLS (Online Web Library System for DIHS)
**Date:** 2026-11-13 (updated, latest UI polish pass)  
**Scope (users/tasks):** DIHS student/borrower and librarian/admin tasks across key flows — discover/login/register, browse catalog and view book details, request to borrow and track status/history, admin checkout/approve/decline/return/edit transactions, manage borrowers, and view/print reports.  
**Devices reviewed:** Desktop-focused implementation review with responsive CSS/markup inspection for smaller viewports (live browser re-sampling limited in this pass due to environment/runtime constraints).  
**Method/Evidence:** Single-evaluator (AI-assisted) heuristic review using prior live browser sampling, console findings, and current Razor/CSS/controller/code inspection after refinements. User-provided screenshots could not be directly viewed by this model; fixes were applied from reported issues and code-level UI audit.  
**Evaluator:** Single review (not a substitute for 3–5 independent evaluators or user testing).

## Summary
- **1 severity-4 (fixed), 2 severity-3, 10 severity-2, 3 severity-1, 0 severity-0 findings** identified across review passes.
- **Biggest resolved risk:** a JavaScript runtime error (`bootstrap is not defined`) broke modal-dependent behavior; this was fixed.
- **Latest fixes applied in this pass (frontend-design refinements, preserving Roboto + existing palette):**
  1. **Top bar redesigned:** cleaner sticky header, improved spacing/alignment, refined brand mark, simplified authenticated identity display (initials + **Full Name** + role) instead of crowded/unstyled chip text, and improved mobile nav behavior.
  2. **Auth pages (Login/Register) restyled for fit and spacing:** consistent auth layout/shell, clearer hierarchy, balanced card padding, improved input-group alignment, and a fully redesigned Register page matching Login.
  3. **Borrow Books page spacing/hierarchy improved:** better page header rhythm, section/filter intro and spacing, stat tile/filter card padding, and clearer catalog guidance while keeping existing workflow and components.
  4. **Search bars and shared UI consistency maintained:** standardized `search-field` styling and consistent spacing tokens across key list/filter pages.

## What works well
- **Consistent visual identity preserved:** Roboto typography and existing OWLS green palette/layout patterns remain intact across improvements.
- **Clear library workflow:** request → approve/decline → borrow/return with due dates, overdue handling, penalties, and inventory updates are surfaced in UI.
- **Role-aware navigation and actions:** borrower/admin experiences are separated and task-focused.
- **Improved borrower experience:** dedicated borrow page consolidates browsing, requests, and status/history tracking with in-app confirmation modal.
- **Useful admin/report surfaces:** actionable transaction queues, borrower details, and real-data analytics/report outputs.

## UI/Frontend improvements applied in this pass (font & color scheme preserved)
- **Top bar:** shows user **Full Name** (claim-based) instead of email where available, with avatar initials/name/role chip and responsive layout refinements.
- **Search bars:** unified `search-field` component styling/markup across catalog, transactions, borrower borrow page, and borrowers management for consistent look and behavior.
- **Confirmation modal:** borrow request uses a centered modal card with dimmed/blurred backdrop.
- **Accessibility/UX polish:** skip-to-content, landmarks/IDs, alert roles/labels, and focus/clarity refinements.
- **No font or color-scheme changes:** Roboto and existing palette/design tokens preserved.

## Limits and next steps
- **Single-evaluator** review with targeted live browser sampling and code inspection; not equivalent to 3–5 independent evaluators.
- Not every state/device permutation was exhaustively exercised (all empty/loading/error states, full CRUD validation permutations, and comprehensive mobile device runs).
- **Validate** severity-3/4 and core workflows with 5 users (borrow request/status tracking, librarian approval/return, report filtering/print).
- **Open recommendations:** add local hero asset, add status legend microcopy, and continue progressive enhancement for dense small-screen tables/charts.
