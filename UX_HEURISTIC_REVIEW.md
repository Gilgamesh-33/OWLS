# Heuristic Evaluation: OWLS (Online Web Library System for DIHS)
**Date:** 2026-11-13  
**Scope (users/tasks):** DIHS student/borrower and librarian/admin tasks across key flows — discover/login/register, browse catalog and view book details, request to borrow and track status/history, admin checkout/approve/decline/return/edit transactions, manage borrowers, and view/print reports.  
**Devices reviewed:** Desktop (browser sampling) with responsive code inspection for smaller viewports.  
**Method/Evidence:** Single-evaluator (AI-assisted) review using live browser sampling on `http://localhost:5123` (home, login, catalog, book details, transactions, borrowers/users, reports), console inspection, and Razor/CSS/controller code review. Screenshots were not persisted as artifact files in-repo during this pass; findings cite observed page/URL locations and code evidence.  
**Evaluator:** Single review (not a substitute for multi-evaluator review or user testing).

## Summary
- **1 severity-4 (fixed), 2 severity-3, 5 severity-2, 4 severity-1, 0 severity-0 findings** identified in this pass.
- **Biggest risk:** A JavaScript runtime error (`bootstrap is not defined`) broke modal-dependent UI behavior on pages; this was found during live evaluation and fixed.
- **Top fixes applied/requested:**
  1. Replaced browser `confirm()` borrow prompts with a **centered confirmation card/modal** and dimmed/blurred backdrop; fixed script ordering so Bootstrap is available before modal initialization.
  2. Added a **dedicated Borrow Books page** for borrowers with catalog search/filters, details access, request actions, and clear sections for pending requests, active borrowed books/due dates/overdue, and borrowing history.
  3. Expanded **Reports & Analytics** with real database-driven charts (borrowing trends, most borrowed, inventory by category, available vs borrowed, status breakdown, returns), date presets/custom range, and print/PDF header with DIHS/OWLS logo, period, generation date, and page-number footer styling.

## What works well
- **Consistent visual identity:** existing green palette, Roboto typography, rounded cards/buttons, and layout patterns were preserved across new/updated pages.
- **Clear library workflow primitives:** request/approve/decline/return logic, due dates, overdue calculation, and inventory adjustments are present and surfaced in UI states.
- **Role-aware navigation:** admins and borrowers see relevant actions/pages, reducing clutter and supporting task focus.
- **Useful operational surfaces:** admin transactions, borrower details, and reports provide actionable summaries, filters, and record-level information.
- **Improved borrower experience:** dedicated borrow page consolidates discovery and status tracking, and confirmation now uses an in-app modal/card with dimmed background.

## UI/Frontend improvements applied (preserving font & color scheme)
- Borrow confirmation changed from native prompt behavior to a **styled modal confirmation card** with dim backdrop/blur.
- Fixed Bootstrap initialization ordering issue affecting modal behavior.
- Enhanced borrower borrow page structure (section icons/headings, guidance copy, status/history grouping).
- Added accessibility/UX refinements: skip link, main landmark targets, alert roles/labels, and small focus/clarity CSS polish.
- Kept existing **Roboto font** and **OWLS/DIHS color palette** throughout.

## Limits and next steps
- This is a **single-evaluator** heuristic review with targeted live browser sampling and code inspection; it will not catch as many issues as 3–5 independent evaluators.
- Browser evaluation in this pass covered sampled states/pages; **not every possible state** (all empty/loading/error permutations, all CRUD validation states, every role-specific edge case, and full mobile device emulation runs) was exhaustively exercised.
- **Validate severity-3/4 and workflow-critical findings** with 5 users on core tasks (student borrow request/status tracking, librarian approval/return, report review/print).
- **Recommended follow-ups:** local hero asset cleanup, status legend microcopy, and further small-screen optimization for dense admin/report tables while maintaining current design language.
